# MOTI Data Factory

מערכת ליצירת דאטה-סט אימון בעברית — 50,000 שיחות טבעיות עבור עוזר ה-AI
האישי **MOTI** (בהשראת JARVIS, אך אנושי וטבעי), לצורך fine-tuning של
`Norod78/Hebrew-GPT2-345M-Stage`.

זה **לא** דאטה-סט כללי של שאלות-תשובות. המטרה היא ללמד את המודל אישיות
עקבית, שיחה טבעית בעברית ישראלית, אינטליגנציה רגשית, הומור והמשכיות
הקשרית לאורך שיחה.

---

## 0. חשוב: זה עולה כסף? (קרא לפני ריצה מלאה)

**אין חיוב נפרד לכל קריאה** — אין כאן מפתח API, הכול רץ דרך ה-login הקיים
שלך ל-Claude Code. אבל זה **כן** צורך מהמכסה של התוכנית שלך (Pro / Max /
אחר) — אותה מכסה שבה אתה משתמש כשאתה מדבר עם Claude רגיל.

מתוך ריצת בדיקה אמיתית: 32 שיחות מאושרות = כ-$0.26 שווה-ערך (מחושב
לפי מחיר רשימה, לא חיוב בפועל). כלומר **~$0.008 לשיחה**. להרצה מלאה של
50,000 שיחות זה שקול לערך ל-**$400-450** של צריכה, פרוסה על פני כ-1,500
עד 1,700 באטצ'ים.

**אם יש לך Claude Pro** (לא Max/Enterprise): זו כמות שימוש גדולה ביחס
למכסה של תוכנית Pro, שמתאפסת כל כמה שעות. המערכת **בנויה לזה**: כשהיא
נתקלת בהודעת "usage limit" היא לא נכשלת ולא עוצרת — היא עוצרת ל-30 דקות
(`rate_limit_wait_sec` ב-`config.json`) ומנסה שוב, עד 10 פעמים ברצף
(`rate_limit_max_retries`), כלומר עד כ-5 שעות המתנה אוטומטית לפני שהיא
בכלל מוותרת על באטצ'. זה אומר שריצה מלאה על תוכנית Pro יכולה לקחת **ימים
של זמן לוח-שנה**, לא רק שעות עבודה בפועל — וזה תקין וצפוי.

**המלצה אם יש לך Pro**: אל תריץ `--generate` ללא הגבלה ותשכח מזה. עדיף:
```bash
python main.py --generate --limit 200
```
תריץ ככה כמה פעמים ביום, תבדוק ב-`--stats` כמה התקדם, ותחליט אם להמשיך.
כך גם נשאר לך שימוש רגיל ב-Claude ליתר העבודה שלך, במקום שהריצה הארוכה
"תתפוס" את כל המכסה שלך.

## 1. איך המערכת עובדת

המנוע המייצר הוא **לא** API בתשלום — הוא ה-CLI של Claude Code שכבר מותקן
במחשב שלך, מופעל כתהליך-משנה (`subprocess`) במצב לא-אינטראקטיבי
(`claude -p`), עם ה-authentication הקיים שלך (אין צורך ב-API key).

```
main.py          ← ממשק שורת הפקודה
generator.py     ← לוגיקת הבאטצ'ים: בחירת קטגוריה, בניית פרומפט, שמירה
claude_client.py ← קריאה ל-CLI של Claude כתהליך-משנה, כולל retries
scenarios.py     ← "מחולל גיוון" — בנקים של נושאים/טונים/מבנים לכל קטגוריה
quality_check.py ← בדיקות איכות: מבניות (דטרמיניסטיות) + סמנטיות (Claude)
deduplication.py ← זיהוי כפילויות מדויקות וכמעט-כפילויות
statistics.py    ← דוחות התקדמות
export_dataset.py← ייצוא לפורמט ה-TXT הסופי
```

### תהליך באטצ' בודד

1. נבחרת הקטגוריה הכי "מפגרת" ביחס ליעד שלה (לפי אחוז השלמה).
2. נבחרים כ-8 "זרעי תרחיש" אקראיים (נושא + טון + מבנה) מתוך `scenarios.py`,
   כדי לאלץ גיוון אמיתי בין באטצ'ים.
3. נשלחת קריאה אחת ל-CLI של Claude, המבקשת 18-30 שיחות שלמות בפורמט JSON
   מובנה (`--json-schema`), בהתאם לאישיות (`prompts/personality.txt`)
   ולכללי היצירה (`prompts/generation_rules.txt`).
4. כל שיחה עוברת **בדיקה מבנית** (Python בלבד, מהיר ודטרמיניסטי): מבנה
   JSON תקין, תפקידי דוברים נכונים ומתחלפים, אורך הודעות, יחס עברית/
   אנגלית, הודעות ריקות, חזרתיות בתוך השיחה.
5. שיחות שעברו את הבדיקה המבנית נבדקות לכפילות **מדויקת** (hash גלובלי)
   ו**כמעט-כפילות** (דמיון Jaccard מול חלון אחרון בקטגוריה).
6. השורדות עוברות **בדיקה סמנטית** — קריאה נוספת ל-Claude, הפעם כ"בוחן
   איכות" שבודק עקביות אישיות, הגיון ועברית טבעית (ראו
   `prompts/quality_evaluation.txt`). אפשר לכבות שלב זה ב-`config.json`
   (`semantic_check_enabled`).
7. שיחות מאושרות נשמרות **מיידית** (לא מצטברות בזיכרון) ל-
   `data/approved/<קטגוריה>.jsonl` וגם ל-`data/approved/all.jsonl`.
   נדחות נשמרות עם הסיבה ל-`data/rejected/<קטגוריה>.jsonl`.
8. קובצי ההתקדמות (`state/progress.json`, `state/category_progress.json`)
   נכתבים מחדש (atomic) אחרי כל באטצ' — זו הבסיס ל-resume.

## 2. התקנה

הדרישה היחידה היא Python 3.9+ ו-Claude Code CLI מותקן ומחובר (מה שכבר
עובד בסשן הזה). אין חבילות Python חיצוניות להתקין:

```bash
cd MOTI_DATA_FACTORY
pip install -r requirements.txt   # ריק בכוונה — רק תיעוד
python main.py --setup
```

`--setup` יוצר את כל התיקיות, בודק שה-CLI זמין, ומאתחל את קובצי המצב.

## 3. הרצת בדיקה (חובה לפני ריצה מלאה)

```bash
python main.py --test
```

מייצר עד 20 שיחות מאושרות (עד 6 באטצ'ים), מריץ עליהן אימות מבני חוזר,
ואם הכול תקין — כותב סמן `state/test_passed.json`.

**`--generate` מסרב לרוץ בלי שהסמן הזה קיים.** זו הגנה מכוונת: אסור
שהמערכת תתחיל ריצה של 50,000 שיחות בלי שאימתת שהאינטגרציה עם ה-CLI
ואיכות הפלט תקינות.

## 4. יצירת הדאטה-סט המלא

```bash
python main.py --generate
```

רץ עד שכל קטגוריה מגיעה ליעד שלה (סה"כ 50,000 שיחות מאושרות — לא רק
"נוצרו", אלא אושרו בפועל; שיחות שנדחות מוחלפות אוטומטית בבאטצ'ים הבאים).
זו הרצה ארוכה (שעות) — אפשר להריץ אותה ברקע:

```bash
nohup python main.py --generate > logs/stdout.log 2>&1 &
```

להרצת בדיקה מוגבלת בכמות (למשל 100 שיחות נוספות בלבד, בלי לרוץ עד הסוף):

```bash
python main.py --generate --limit 100
```

### עצירה והמשכה (resume)

עצירה באמצע (`Ctrl+C`, סגירת טרמינל, קריסה) **לא מאבדת כלום** — כל באטצ'
נשמר לדיסק ברגע שהוא מאושר, וקובצי ה-state נכתבים אחרי כל באטצ'. כדי
להמשיך, פשוט מריצים שוב את אותה פקודה:

```bash
python main.py --generate
```

המערכת תדע בדיוק כמה כבר אושר בכל קטגוריה, ותמשיך משם. דה-דופ (כפילויות)
גם הוא נבנה מחדש מהדאטה הקיים על הדיסק בכל הרצה, כך שלא ייווצרו כפילויות
בין הרצות.

## 5. מעקב התקדמות

```bash
python main.py --stats
```

מציג: סה"כ נוצרו/אושרו/נדחו, שגיאות, עלות מצטברת (הערכה), אחוז התקדמות
עם progress bar, ממוצע הודעות/תווים לשיחה, הערכת באטצ'ים נותרים, והתקדמות
מפורטת לפי כל אחת מ-8 הקטגוריות.

## 6. בדיקת שיחות שנדחו

כל שיחה שנדחתה (מבנית או סמנטית) נשמרת — לא נמחקת — יחד עם הסיבה:

```bash
cat data/rejected/everyday.jsonl | python3 -m json.tool
```

כל רשומה כוללת שדה `rejection_reason`, למשל:
`"structural: message count 2 out of range"` או
`"semantic: התשובה לא עקבית עם האישיות של MOTI"`.
זה שימושי לכוונון פרומפטים (`prompts/`) אם שיעור דחייה גבוה מדי בקטגוריה
מסוימת.

## 8. שינוי גודל היעד או התפלגות הקטגוריות

הכול מוגדר ב-`config.json`:

```json
"target_total": 50000,
"categories": {
  "everyday": { "name_he": "שיחות יומיומיות", "target": 8000 },
  ...
}
```

שנה את `target_total` ואת ה-`target` של כל קטגוריה (מומלץ שסכום היעדים
יתאים ל-`target_total`). אין צורך לגעת בקוד — `pick_next_category` ב-
`generator.py` קורא את זה דינמית בכל באטצ'.

פרמטרים נוספים שכדאי להכיר ב-`config.json`:
- `model` — ברירת מחדל `sonnet`. אפשר להחליף למודל אחר שזמין ב-CLI.
- `batch_size_min/max` — גודל הבאטצ' (18-30 כברירת מחדל).
- `semantic_check_enabled` — האם להריץ את שלב הבדיקה הסמנטית (יקר/איטי
  יותר, אבל קריטי לאיכות האישיות — מומלץ להשאיר דלוק).
- `near_duplicate_jaccard_threshold` — רגישות זיהוי כמעט-כפילויות.
- `subprocess_timeout_sec`, `max_retries_per_batch` — טיפול בכשלים/טיימאאוט.

```bash
python main.py --validate
```

## הערות כנות על מגבלות

- בדיקות Python (מבניות) **לא** מבטיחות עברית "ספרותית" — הן תופסות
  בעיות סטטיסטיות/מבניות (יחס אותיות עברית/לטינית, אורך, חזרתיות).
  האיכות הסמנטית-אנושית נסמכת על שיפוט של Claude, שהוא עצמו לא מושלם —
  לכן שיחות שנדחו נשמרות ולא נמחקות, ולא כל שיחה שעברה אושרה "מושלמת".
- זיהוי כמעט-כפילויות פועל על חלון אחרון לכל קטגוריה (לא כל הדאטה-סט
  מול עצמו — זה היה הופך ל-O(n²) ולא מעשי בקנה מידה של 50,000). זה תופס
  את התרחיש הריאלי (באטצ'ים סמוכים חוזרים על עצמם), לא כל כפילות אפשרית
  תיאורטית בכל הדאטה-סט.
- "זיכרון" של MOTI בקטגוריית `memory_familiarity` הוא זיכרון **בתוך
  אותה שיחה בלבד** — אין ל-MOTI זיכרון אמיתי בין שיחות נפרדות, וה-prompt
  מנחה את הדור בהתאם (לא להמציא פרטים שלא נאמרו בשיחה עצמה).
